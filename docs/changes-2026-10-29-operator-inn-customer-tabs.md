# ИНН туроператоров, вкладки заказчика и порядок задач

В справочник ТО добавлено необязательное строковое поле ИНН: 10 или 12 цифр, с сохранением ведущих нулей. Поле доступно в штатном редакторе и форме справочника; в админке его можно редактировать прямо в списке и искать по нему. Миграция 0039 не подставляет вымышленные ИНН; существующие ТО требуют заполнения.

В выгрузке оператор содержит `inn` в JSON и атрибут `INN` в XML. Единый приёмник 1С v16 ищет действующий элемент справочника «Контрагенты» с таким ИНН; сохранённое соответствие по UUID больше не читается и не записывается. Вся пачка проверяется до первого изменения базы: отсутствие/неверный ИНН, отсутствие контрагента или неоднозначное совпадение останавливают загрузку. Сообщение указывает ТО/ИНН и предлагает заполнить справочник CRM либо добавить/исправить контрагента в 1С и повторить. Диалог выбора ТО не используется, создание контрагента 1С не автоматизируется. Заказчики-физлица остаются с идентификацией по ФИО согласно прежним правилам. Старые XML без атрибута INN нужно сформировать заново после заполнения ТО.

Собран комплект `/workspace/artifacts/CRM_1C_Unified_v16.zip`. Сборка проверяет состав модуля и неизменность остальных потоков формы. Запуска 1С 7.7 в среде нет: требуется проверка в пользовательской тестовой базе.

Карточка заказчика содержит вкладки «Данные заказчика», «Договоры», «Задачи», «Финансы», «Похожие записи» с сохранением существующих прав доступа и защиты несохранённых данных. Пагинация задач/финансов сохраняет активную вкладку. Похожие физлица определяются по совпадению нормализованного полного ФИО, телефона либо email; организации — по ИНН. Это список для ручного сравнения, объединение/удаление не выполняется.

В договоре задачи сортируются по `done, due, pk`: запланированные первыми, затем от раннего срока к позднему; выполненные после них. Просроченные запланированные стоят перед будущими.
