# Заказчики

Пункт «Заказчики» в основном меню и в шапке управления открывает `/customers/`. Старый административный справочник остаётся доступным в настройках.

- Поиск по ФИО/организации/ИНН, телефону (включая дополнительные) и e-mail. Русские имена и e-mail сравниваются без регистра; телефоны +7/7/8 и с разделителями приводятся к общему формату.
- Отбор физических/юридических лиц. Колонки: заказчик, тип, телефоны, e-mail, ИНН, количество договоров. Все колонки сортируются и имеют фильтр с несколькими значениями; число договоров сортируется как число.
- Видимость/порядок колонок сохраняются отдельно от других журналов. Условия и страница сохраняются при возврате из карточки и других разделов. Сброс очищает фильтры этого справочника. На странице до 100 записей; паспорта в журнал не выводятся.
- «+ Новый заказчик» (`/customers/add/`) и нажатие на имя открывают карточку в основном интерфейсе. Используется существующая форма физлица/юрлица с трёхколоночной сеткой, автоматическим ФИО и реквизитами организации. Распознавание паспорта использует существующий локальный OCR; фотографии не записываются вместе с карточкой. Для юрлица кнопка паспорта скрыта, примечание остаётся доступным.
- В карточке видны последние 100 договоров и общее количество, при наличии права просмотра договоров. Похожие записи показываются по совпадению имени/контактов для физлиц и ИНН для юрлиц. Это подсказки для проверки, а не автоматическое объединение; данные не переносятся между людьми.
- Просмотр требует view_customer. Создание — также add_customer, сохранение существующего — change_customer. Пользователь только с просмотром видит заполненную карточку без редактирования и загрузки паспорта. Финансы/договоры без соответствующего права не выводятся.
- Сохранение проверяет версию всей карточки; устаревшая форма не затирает правки другого окна. Изменения записываются в историю и обновляют версии связанных договоров. Существующий POST `/customers/new/` для диалога заказчика в договоре сохранён.

В этом пакете кнопка «Копировать» финансовой операции перенесена вправо в шапку, как в договоре. Исправлены адреса файлов скриптов форм: реальные версионные имена static-файлов используются вместо query-параметров внутри Django Media, чтобы автоматическое ФИО и загрузка договоров по заказчику работали и в административных формах.

Миграции не требуются. После первоначальной установки службы обновления пакет устанавливается через «Справочники и управление → Обновление CRM → Установить обновление».
