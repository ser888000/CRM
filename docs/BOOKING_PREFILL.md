## Обновление v7 — очистка и дата выбранного тура

Скрипт сайта: `booking_prefill.js?v=7`. Заменить версию существующего подключения, не добавлять второй скрипт.

Кнопка очистки работает после смены тура и перерисовки формы: туристы сопоставляются по минимум двум идентификационным полям, удаляются только значения, записанные помощником. Ручные изменения сохраняются. Снимок хранится только в памяти страницы; после полной перезагрузки страницы он недоступен. Кнопка диагностики убрана.

Дата читается из видимой календарной опции карточки выбранного тура. Согласно фактическому `getDateNightOptionSettings` Турвизора, год скрыт только для текущего года. Явный год учитывается; невалидная или неоднозначная дата требует ручного ввода. Дата старого договора для возраста не используется.

Проверка: 11 DOM-тестов, включая перенос состояния на другую форму и распознавание даты с годом и без года. Требуется проверка на живой странице после обновления CRM и подключения v7.

## Текущий сценарий v6

Используется старый договор только как источник людей. В открытой карточке нажать «Данные в Турвизор» (сразу после «Сверить с Турвизором», если эта ссылка есть). В панели больше нет обязательного выбора договора и общей подтверждающей операции при совпадении состава. Подключение: booking_prefill.js?v=6 вместо v5.

Возраст рассчитывается сервером на явную дату новой поездки из параметра start. Дата старого договора не подставляется, сам договор/туристы не изменяются, новый договор не создаётся. После ручного бронирования пользователь импортирует новую заявку Турвизора штатным импортом. При смене тура дата в панели очищается.

Если подходящих людей больше, чем мест, диалог предлагает выбрать туриста для каждого возрастного слота или оставить поле пустым. Один человек не может занять несколько мест. Если людей меньше или возраст ребёнка не соответствует форме, подходящие переносятся, остальные места остаются для ручного ввода. Неподходящие возрасту дети не вставляются в чужой слот. Точные детские возраста распределяются до гибкого «до2лет». Ошибки отдельного человека (нет ДР/пола/имени/неверная латиница) больше не блокируют всех: такой турист не назначается, причина показывается в панели. Несовпадение гражданства/типа документа конкретного туриста также оставляет это место для ручного ввода. Заказчик передаётся отдельно.

Добавлены частичное заполнение, выбор лишних взрослых/детей, запрет двойного выбора, отмена без изменений, возраст на новой дате без изменения исходного договора и прямой возврат после подготовки. Сам браузерный скрипт дополнительно ограничен этим сайтом, точным путём и наличием модуля898. Пользовательские паспортные/контактные данные не запрашиваются: сервер выдаёт только фиксированный фиктивный пример. Ответы no-store, Vary Origin/Cookie. GET не меняет бизнес-данные.

Проверки выполняются на имитации публичного интерфейса модуля, не доказывают совместимость реальной формы. ## Проба v3 — фактический runtime сайта

Пользователь подтвердил: initTv undefined, TV object, orderCatalog undefined даже при открытой форме. Поэтому схема позднего копирования TV2 не подтверждена для данной страницы. ## Проба v4 — подстановка через фактические поля

Отчёт с пользовательской страницы подтвердил: TV экспортирует только getRequestId/loadModules, iframe нет, форма находится в DOM страницы. Обход через initTv/orderCatalog удалён. Подстановка использует классы видимых TVTourBuyTouristItemControl/TVTouristSurname/TVTouristName/TVTouristBirthday/TVPassport* и TVCustomerContacts*, полученные из отчёта без значений. В публичном исходнике InputNew подтверждён обработчик события input, который вызывает Changed; blur обновляет маску/подпись.

Требуются ровно2видимых взрослых блока и по одному доступному полю каждого вида. Все23поля проверяются на наличие и отсутствие персональных значений до первого изменения; маски и пустой префикс+7 допускаются. Запись использует нативный setter input.value и события input/change/blur; элементы переполучаются после событий. Пол/гражданство/чекбоксы согласия не меняются. Нет вызовов закрытого API/отправки формы/нажатия кнопок модуля. При отсутствии поля проба прекращается до записи. Восстановление ограничено тем же hash и теми же элементами формы; при переходе в другой тур/пересоздании формы оно запрещено.

Шесть JS-тестов теперь работают в jsdom на анонимной разметке с фактическими классами: заполнение23полей без приватного TV API и вызов обработчиков input, восстановление, неизменность постороннего поля, отказ при исходных данных/отсутствующем поле/другом туре/пересоздании формы, диагностика без значений/секретов. Это моделирование DOM, а не выполнение живого модуля Турвизора; реальную реакцию и маски проверяет пользователь. Тестовая зависимость jsdom установлена только во временный каталог, команда запуска указана в scripts/test_booking_prefill.js. Подключение — ?v=4.

## Рабочий поток v5 — сохранённый договор CRM

В договор добавлена POST-кнопка «Подготовить для бронирования». Выбор хранится30минут в серверной сессии: только PK/UUID договора и срок действия, без копирования паспортных данных. Отдельная страница /booking-prefill/select/ позволяет выбрать договор по номеру/заказчику; поле UUID защищает от ошибочного повторного использования ID после замены базы. Подстановка работает по сохранённым значениям, поэтому правки карточки сначала нужно сохранить.

На сайт вместо booking_prefill_demo.js подключается booking_prefill.js?v=5. Статус и данные доступны только активным пользователям с view_contract/view_customer/view_tourist, с точным разрешённым Origin и credentials. При начальном показе панели запрашиваются только метаданные выбранного договора. Полные данные выбранного договора получаются при ручном нажатии, только из серверной сессии, не по произвольному ID из URL. Все ответы no-store, Vary Cookie/Origin; ключи API и личные данные в URL/локальное хранилище не помещаются.

Туристы берутся из связанных строк договора, один Tourist учитывается один раз даже при нескольких ценовых строках. Заказчик из Customer передаётся отдельно, автоматически в туристы не добавляется. Возраст рассчитан на Contract.start с учётом дня рождения; сортировка по дате рождения от старших к младшим. Взрослые сопоставляются последовательно; дети — по точному возрасту заголовка, «до2лет» допускает возраст0/1. Точные возрастные слоты распределяются раньше гибких, чтобы младенческий слот не забрал единственного подходящего годовалого ребёнка. Отсутствие ДР/имени/пола, будущая ДР и неверная латиница при загранпаспорте блокируют выдачу. Юрлицо в качестве покупателя пока не поддерживается этой формой.

Перед записью сверяется весь состав и доступность полей. Подстановка показывает подтверждение: номер договора, дату начала, заказчика, порядок туристов/ДР/возраст и незаполненные поля. Используется дата начала договора; соответствие даты выбранному туру проверяется сотрудником в этом окне. Гражданство проверяется с текущим значением формы; если оно различается, запись останавливается. Пустое гражданство/тип документа и неполные паспортные поля требуют ручной проверки, не угадываются. Латиница не транслитерируется автоматически. Пол выставляется только переключателем в конкретном блоке туриста, через подтверждённое событие click radio; нажатия отправки/оплаты и отметки согласий отсутствуют. Существующие значения не заменяются. Восстановление доступно только для тех же элементов той же формы/тура.

Проверено256тестов Django и5DOM-тестов рабочего потока: группа4взрослых+2детей с перепутанными возрастными слотами, сочетание точного возраста1год и гибкого «до2лет», сортировка взрослых, пол, отдельный заказчик, восстановление, отмена подтверждения, запрет перезаписи и отсутствие изменения согласий. Дополнительные серверные тесты проверяют CSRF выбора, Origin/права/истечение сессии, дедупликацию туристов и возраст в день рождения. Реальные персональные данные в тестовых/репозиторных файлах не сохранялись. Пользователь ранее подтвердил ввод событий вживую на синтетическом v4; новый поток с реальными договорами требует пользовательской проверки без отправки тестового бронирования.
