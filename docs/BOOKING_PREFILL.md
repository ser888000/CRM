# Тест подстановки в модуль Турвизора898

Стадия: прототип на синтетических данных. Не проверен в живой форме сайта. Реальные данные договоров и создание бронирования не подключены.

После обновления CRM добавить скрипт из docs/site/booking-prefill-demo.html на страницу /book/offers_tourv.php рядом с существующим init.js. Войти в CRM в том же браузере и открыть страницу бронирования. Панель «CRM · тест для сотрудника» создаётся только после успешного авторизованного GET к /booking-prefill/demo/. Доступ: активный пользователь с crm.view_contract. Куки отправляются только в CRM. Обычному посетителю/пользователю без права сервер возвращает403 без данных, панель не создаётся. Неавторизованный ответ не перенаправляет на страницу входа и не показывает посетителю технические ошибки.

Origin разрешён только https://aborigen-tour.ru и https://www.aborigen-tour.ru, с точным совпадением и CORS credentials. Сам браузерный скрипт дополнительно ограничен этим сайтом, точным путём и наличием модуля898. Пользовательские паспортные/контактные данные не запрашиваются: сервер выдаёт только фиксированный фиктивный пример. Ответы no-store, Vary Origin/Cookie. GET не меняет бизнес-данные.

В пустой форме на2взрослых нажать кнопку заполнения. Тест сохраняет Id/Age/AgeGroup/DocumentType/гражданство, подготовленные модулем, и задаёт имена/даты/документы двух вымышленных туристов и заказчика. Введённые персональные поля блокируют тест без замены. Доступ к TV.orderCatalog проверяется до записи. Для обновления интерфейса проверяются известные внутренние контролы; если контрол недоступен, интерфейс предлагает повторно открыть форму. Реальный результат внутреннего API ещё требует проверки на сайте; это не документированный публичный контракт Турвизора.

Заявка не отправляется, согласия не отмечаются, переход к оплате не запускается. Панель явно предупреждает о тестовых данных. Кнопка восстановления возвращает снимок модели и пытается перерисовать форму; после смены тура восстановление отменяется. Данные не передаются в URL/буфер обмена/localStorage нашим скриптом.

Проверки:3 теста серверного доступа/Origin/методов/кеша,4 JavaScript-теста с моделью: невидимость для посетителя, только ручной запуск/восстановление, запрет перезаписи, запрет восстановления другого тура. Проверки выполняются на имитации публичного интерфейса модуля, не доказывают совместимость реальной формы. Перед передачей настоящих данных нужно подтвердить обновление видимых полей и состояние, которое модуль использует для отправки.

## Проба v2

На сайте панель появилась, но в открытой форме window.TV.orderCatalog оказался недоступен. В загруженном core.min.js window.initTv копирует накопленные TV2-экспорты в window.TV; дополнительные части модуля могут загружаться позже этого копирования. Перед доступом к каталогу теперь вызывается имеющийся initTv, затем повторяется проверка методов. Если API всё ещё недоступен, панель выводит только имена/типы объектов и функций, без значений персональных полей. Сценарий позднего экспорта проверен пятым JavaScript-тестом; реальный результат требуется повторить на сайте. Подключение скрипта — ?v=2 для обновления кеша.

## Проба v3 — фактический runtime сайта

Пользователь подтвердил: initTv undefined, TV object, orderCatalog undefined даже при открытой форме. Поэтому схема позднего копирования TV2 не подтверждена для данной страницы. Добавлена отдельная кнопка копирования диагностики: имена TV-экспортов, адреса JS/iframe без query/hash и видимая структура полей (тип, name/id, placeholder, классы родителей). Значения input/select/textarea не читаются, бизнес-запросов нет. Диагностика доступна только в уже авторизованной панели и копируется по нажатию; не отправляется автоматически на сервер. Тест с запрещающим чтение .value и URL с секретом подтверждает отсутствие значений/секретов в отчёте. Все6 JS-тестов прошли. Для установления способа реальной подстановки нужен отчёт из браузера пользователя; прямой доступ к странице из среды по-прежнему отклонён.
