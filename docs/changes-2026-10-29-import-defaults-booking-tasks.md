# Значения по умолчанию при импорте, брони и задачи

Новые договоры при любом импорте из Турвизора (одиночном/групповом, через общий apply_order) получают тип договора и основной способ оплаты из действующих записей справочников с признаком «по умолчанию». Валюта предложения берётся из действующей валюты по умолчанию, а не из валюты стоимости API. Рублёвая стоимость Турвизора не конвертируется: прежняя проверка валюты суммы API сохранена. Если соответствующая настройка не задана, остаются прежние значения (тип/способ пустые, валюта API RUB). Повторная сверка существующего договора не заменяет выбранные тип/способ/валюту, валюта предложения не предлагается как изменение из Турвизора.

Во вкладке «Брони ТО» добавлена кнопка удаления каждой брони с подтверждением. POST проверяет delete_booking, принадлежность брони договору, актуальность версии и CSRF; удаление записывается в аудит, версия договора обновляется. Договор и финансовые операции не удаляются.

Общий срок оплаты ТО перенесён в «Финансы → Расчёт с туроператором» и называется «До какого числа оплатить ТО». Размещён в одной строке со статусом расчёта, сохранение возвращает в «Финансы». Значение в базе прежнее, повторного ввода не требуется.

В задачах договора установлен порядок done, -due, pk: сначала запланированные, внутри группы свежие сроки раньше старых. Это заменяет прежнюю сортировку по возрастающей дате.

В отдельном редакторе новой/существующей задачи поле done представлено цветной кнопкой «Запланировано / Выполнено». Кнопка меняет скрытое булево поле и отмечает несохранённые изменения; запись выполняется штатным сохранением задачи вместе с прочими полями, аудитом и проверкой версии. JS не отправляет форму автоматически. Правила повторяющихся задач сохранены.

Проверки: 292 теста Django и 2 DOM-теста переключателя прошли. Миграций базы для этих изменений нет.
