# Перенос истории из старой CRM

## Согласовано с владельцем

- Старую CRM продолжают использовать до проверки полноценного переноса. После тренировок данные новой CRM будут очищены перед окончательной загрузкой. Пока очистка не выполняется.
- Массовый перенос истории из Tourvisor не нужен: эта история остаётся в Tourvisor.
- Перенести заказчиков, договоры, строки туристов в договорах, клиентские платежи, задачи, примечания, необходимые справочники и связи между сущностями.
- Туристов переносить как строки конкретного договора; отдельный справочник туристов ими не заполнять.
- Брони туроператоров не переносить.
- Отдельных операций оплаты ТО в источнике нет. Есть поле суммы, заплаченной ТО, и дата последнего платежа, обозначающая полный расчёт. Сохранить исходные значения и их смысл; не изображать отсутствующую историю платежей ТО выдуманными операциями. Способ хранения в новой CRM определить после изучения схемы.
- Под «прикреплёнными документами» требуется уточнить: имеются ли реальные файлы (сканы и т.п.) либо речь о документах учётной системы и их связях с заказчиком, платежами и задачами.
- Доступ к базе на Masterhost есть. По прежним скриншотам: Microsoft SQL Server 2016, база u340795_crm. Название старой CRM и соответствие базы рабочей истории нужно подтвердить.

## Порядок работ

1. Выяснить доступность резервной копии .bak или SQL-подключения к базе. Начать с чтения структуры: таблицы, поля, ключи и связи. Подготовлен scripts/legacy_schema.sql; он не меняет базу и не выгружает содержимое клиентских записей.
2. Составить карту соответствия сущностей и справочников, отдельно проверить строки туристов, типы/знаки клиентских платежей, сумму расчётов с ТО, даты и примечания. Уточнить местонахождение файлов, если они есть.
3. Подготовить воспроизводимый тренировочный импорт со стабильными исходными идентификаторами, журналом пропусков/ошибок и сверкой связей. До полного импорта проверить небольшую связанную выборку на копии источника.
4. Сверить количество договоров/заказчиков/задач, суммы договоров, клиентских платежей, возвратов и агрегатов ТО. Отдельно проверить незакрытые договоры, долги, отмены, задачи и документы.
5. После проверки тренировочного полного импорта согласовать момент прекращения записей в старую CRM, получить финальный снимок, очистить тренировочные данные новой CRM с резервной копией и загрузить актуальную историю. Удаление данных — отдельный этап перед рабочей загрузкой, сейчас не выполняется.

Прямое чтение SQL или работа с резервной копией может позволить обойтись без запуска старого клиента. Если он понадобится для понимания полей/отчётов, сначала рассмотреть отдельную виртуальную Windows вместо переустановки рабочего компьютера.
