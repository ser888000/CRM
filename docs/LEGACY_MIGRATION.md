# Перенос истории из старой CRM

## Согласовано с владельцем

- Старую CRM продолжают использовать до проверки полноценного переноса. После тренировок данные новой CRM будут очищены перед окончательной загрузкой. Пока очистка не выполняется.
- Массовый перенос истории из Tourvisor не нужен: эта история остаётся в Tourvisor.
- Перенести заказчиков, договоры, строки туристов в договорах, клиентские платежи, задачи, примечания, необходимые справочники и связи между сущностями.
- Туристов переносить как строки конкретного договора; отдельный справочник туристов ими не заполнять.
- Брони туроператоров не переносить.
- Отдельных операций оплаты ТО в источнике нет. ADD_SUM_OPLATY_TO — текущая фактически перечисленная сумма (возвраты уже вычтены). При наличии ADD_DATE_OPLATY_TO расчёт с ТО завершён на 100%, сумма является итоговой себестоимостью; без даты сумма промежуточная и возможны новые платежи. Не создавать выдуманную историю операций ТО; предусмотреть отдельный начальный агрегат при расчёте себестоимости нового договора.
- Прикреплённые файлы переносить только для библиотеки. Вложения к заказчикам и документам исключить. Связи заказчиков с договорами, платежами и задачами сохранить.
- Раздел «Библиотека» использовался и включён в перенос. На скриншоте — дерево разделов и форматированные тексты. В базе найдена LIST_INFO_BASE с родительскими связями и текстами RTF; содержимое и формат должны сохраниться.
- Резервная копия u340795_crm MSSQL получена в ZIP, проверена и восстановлена в отдельной среде без внешней сети. SQL Server 2016 подтверждён заголовком; RESTORE VERIFYONLY и DBCC CHECKDB завершились без выявленных ошибок. Исследуемая копия переведена в READ_ONLY. Рабочая база и новая CRM не менялись.
- На компьютере супруги доступен старый клиент CRM. Из интерфейса можно экспортировать таблицы в Excel; другого экспорта или доступа к данным нет. Основной источник переноса — БД; Excel оставить для точечной сверки и расшифровки полей, массовый экспорт сейчас не нужен.
- Доступ к базе на Masterhost есть. По прежним скриншотам: Microsoft SQL Server 2016, база u340795_crm. Название старой CRM и соответствие базы рабочей истории нужно подтвердить.

- По подтверждению владельца: документы типов «СЧЕТ» и «ПКО» не переносить. Записи корзины (помеченные удалёнными) не переносить. Согласованное исключение: восстановить только необходимых удалённых заказчиков, на которых ссылаются переносимые действующие договоры, платежи или задачи, чтобы сохранить связи.

## Порядок работ

1. Выяснить доступность резервной копии .bak или SQL-подключения к базе. Начать с чтения структуры: таблицы, поля, ключи и связи. Подготовлен scripts/legacy_schema.sql; он не меняет базу и не выгружает содержимое клиентских записей.
2. Составить карту соответствия сущностей и справочников, отдельно проверить строки туристов, типы/знаки клиентских платежей, сумму расчётов с ТО, даты и примечания. Изучить содержимое и связи раздела «Библиотека»; при необходимости сравнить с экраном или точечным экспортом Excel.
3. Подготовить воспроизводимый тренировочный импорт со стабильными исходными идентификаторами, журналом пропусков/ошибок и сверкой связей. До полного импорта проверить небольшую связанную выборку на копии источника.
4. Сверить количество договоров/заказчиков/задач, суммы договоров, клиентских платежей, возвратов и агрегатов ТО. Отдельно проверить незакрытые договоры, долги, отмены, задачи и документы.
5. После проверки тренировочного полного импорта согласовать момент прекращения записей в старую CRM, получить финальный снимок, очистить тренировочные данные новой CRM с резервной копией и загрузить актуальную историю. Удаление данных — отдельный этап перед рабочей загрузкой, сейчас не выполняется.

Прямое чтение SQL или работа с резервной копией может позволить обойтись без запуска старого клиента. Если он понадобится для понимания полей/отчётов, сначала рассмотреть отдельную виртуальную Windows вместо переустановки рабочего компьютера.


Черновик сопоставления по схеме: [LEGACY_MAPPING_DRAFT.md](LEGACY_MAPPING_DRAFT.md). Полная диагностика и реальные данные хранятся отдельно от репозитория.

## Первый тренировочный этап: библиотека

Подготовлен отдельный импорт библиотеки через браузер: меню «Библиотека» → «Загрузить старую библиотеку» (только суперпользователь). Загружается подготовленный ZIP, не SQL Server .bak. Описание формата: [LEGACY_LIBRARY.md](LEGACY_LIBRARY.md). Договоры, заказчики и финансы этот импорт не изменяет. Остальная история пока не загружена.

Тексты доступны для поиска и копирования; исходный RTF и вложения сохраняются байт в байт и скачиваются только после авторизации. Отображение в браузере текстовое: исходное форматирование доступно в оригинале. Раздел с отсутствующим родителем сохраняется в корне с замечанием в журнале. Идентичный пакет не создаёт дубликатов и не перезаписывает ручные правки; изменённый снимок того же источника требует отдельной сверки.

## Тренировочный перенос истории подготовлен

- Суммы договоров и себестоимость в рублях — подтверждено владельцем, другие валюты не используются. Несогласованные старые коды валют не служат основанием для пересчёта.
- Итог договоров брать из шапки; исходные строки сохранить, разницу явно показывать.
- Платежи без существующего договора оставить в отчёте для последующего разбора, не разносить автоматически. Нулевые записи сохранить в архиве без денежного движения.
- Реализованы фоновая загрузка, резервная копия, атомарная запись, исходные снимки и защита от повторного импорта. Проверено на отдельной локальной базе; рабочая новая CRM автоматически не загружалась.
- Сверка и установка: [LEGACY_HISTORY.md](LEGACY_HISTORY.md). Очистка тренировочных данных пока не выполняется.

## Согласование тренировочных данных
