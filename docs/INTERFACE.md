# Компактный интерфейс CRM

Справа вверху — выбор темы: «Классический офис», «Учётная система» и «Табличный режим». По умолчанию используется «Учётная система». Левое меню сохраняется. Обе основные темы используют строку поиска непосредственно под заголовками колонок, а прежний выбор значений через стрелку тоже доступен.

Тема и ширина колонок хранятся в `UserInterfacePreference` для текущей учётной записи и доступны после входа с другого компьютера. Пользователи выбирают оформление независимо; если два человека входят под одним логином, настройки будут общими. Административный интерфейс Django не перекрашивается.

## Таблицы

- Договоры, задачи, заказчики и финансы выводят весь отфильтрованный список без разбивки на страницы. Старые ссылки `page=2` открывают тот же полный список. Списки связанных записей в карточке заказчика сохраняют прежнюю отдельную навигацию.
- Шапка, фильтры под ней и строка «Итого» закреплены в прокручиваемой области. В договорах первые две видимые колонки продолжают закрепляться слева.
- Перетаскивание правой границы заголовка меняет ширину. Ширина сохраняется отдельно для каждой таблицы и пользователя. Порядок колонок и их видимость продолжают использовать существующие настройки браузера.
- Двойной щелчок по границе подбирает ширину по содержимому; доступно также изменение стрелками клавиатуры после Tab на границу. «Сбросить ширину колонок» возвращает исходные размеры. При ошибке сохранения показывается сообщение, изменение откатывается к сохранённому значению.
- Поиск под колонкой означает «содержит текст» и применяется Enter или кнопкой «Применить фильтры колонок». Он работает на сервере по всем записям списка, а не только по видимой части. Условия нескольких колонок объединяются через И. Старый фильтр по набору значений учитывается одновременно.
- Фильтры `q_<колонка>` сохраняются в прежних условиях журнала и учитываются в выгрузке договоров в 1С через тот же `journal_context`.

## Итоги

В договорах суммируются сумма, оплачено, долг, себестоимость, доход, взрослые и дети. В финансах суммируются поступление и расход; для курса выводится среднее с подписью «Ср.», поскольку курсы не складываются. У заказчиков суммируется количество договоров. В задачах показано количество записей. Номера документов, ИНН, телефоны и даты не трактуются как суммируемые числа.

Все итоги вычисляются после применения условий периода, поиска и фильтров колонок по всему отфильтрованному набору. Скрытие/перестановка/ширина колонок меняют представление, а не состав расчёта.

## Развёртывание и проверка

Миграция 0042 создаёт только настройки интерфейса; договоры, задачи и финансы не изменяет. Штатное обновление CRM применяет миграцию. `/preferences/interface/` требует входа, POST защищён CSRF; нельзя выбрать другого пользователя, записать произвольную тему или неограниченную ширину. Настройки изменяются частично, чтобы ширина одной колонки не стирала остальные.

Проверено: 349 тестов Django; DOM-тесты изменения ширины, порядка/скрытия и сохранения статуса задач; Playwright на отдельной синтетической SQLite-базе: смена/сохранение темы, drag-resize с перезагрузкой, фильтры, четыре журнала, закреплённые итоги, карточка договора и мобильная навигация. Рабочая БД в разработке не использовалась.
