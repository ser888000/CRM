# Тренировочный перенос библиотеки

После обновления CRM открыть «Библиотека» → «Загрузить старую библиотеку», выбрать подготовленный ZIP. Доступ к загрузке только у суперпользователя; просмотр и скачивание требуют права просмотра библиотеки. Пакет содержит реальные данные: хранить вне Git и публичных каталогов.

Пакет переносит дерево разделов, названия, тексты и только вложения библиотеки. Клиенты, договоры, задачи и финансы остаются без изменений. Исходные RTF и файлы хранятся в базе, поэтому входят в существующее резервное копирование SQLite. В браузере показан текст с кликабельными ссылками; оформление RTF сохраняется в скачиваемом оригинале.

Повторная загрузка идентичного содержимого не создаёт дубликатов и сохраняет ручные правки. Загрузка изменённого снимка поверх импортированных записей блокируется до отдельной реализации сверки. Если после импорта удалены записи/файлы, повтор также останавливается. Операция атомарная, контрольные суммы проверяются до записи. Отсутствующий родитель отмечается в журнале; раздел сохраняется в корне. Циклы отклоняются.

## Подготовка

`scripts/export_legacy_library.py OUTPUT.zip` запускается в изолированной среде SQL Server с pymssql и переменной MSSQL_SA_PASSWORD. Разрешена только база legacy_crm в READ_ONLY; пароль не передаётся аргументом. Сценарий рассчитан на исследованную структуру Masterhost и дату текущего снимка; для финального снимка дату следует обновить. Не подключать его к рабочей БД.

Альтернатива браузеру: `python manage.py import_legacy_library PACKAGE.zip --dry-run` проверяет пакет без изменения базы; без --dry-run загружает его. --actor задаёт идентификатор пользователя журнала. Конвертация текстов выполняется при загрузке, поэтому пробный импорт на отдельной БД нужен дополнительно к --dry-run.

## Формат пакета

ZIP до 8 МБ, распакованный объём до 64 МБ. Файлы не извлекаются на диск. В корне manifest.json:

```json
{
  "format": "aborigen-legacy-library-v1",
  "source_key": "legacy:example",
  "snapshot": "2026-10-25T01:35:50",
  "items": [{
    "id": 1, "parent": -1, "title": "Раздел",
    "encoding": "cp1251", "original_b64": "",
    "sha256": "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855"
  }],
  "files": []
}
```

Вложения: id, entry_id, name, notes, member (`files/ID.bin`), sha256 и необязательный meta с attached_at/resaved_at. ID сохраняют исходные ключи; источник вместе с ID обеспечивает сопоставление. Проверяется отсутствие посторонних файлов и корректность всех связей/контрольных сумм. Оригинал текста до 1 МБ, отдельный файл до 16 МБ. В Git допустимы только вымышленные примеры.
