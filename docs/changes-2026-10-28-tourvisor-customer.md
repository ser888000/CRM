# Обновление заказчика и граница импорта Турвизора

Новые заявки Турвизора разрешены начиная с ID2299358 включительно. Проверка стоит перед одиночным запросом, в списке группового импорта и в транзакционном apply_order; старый предпросмотр/прямой вызов не обходят ограничение. Сверка уже связанных с Турвизором договоров остаётся доступной. История старой CRM не затрагивается.

При выборе существующего заказчика на первом импорте по умолчанию сохраняются его реквизиты. Доступны «Сравнить данные заказчика» и отдельный выключенный флажок обновления. Сравнение использует именно выбранную карточку и не создаёт договор. Смена выбора снимает флажок. При подтверждении обновляется эта общая карточка, включая её использование в других договорах; предупреждение присутствует в форме. Местные примечания/дополнительные контакты, отсутствующие в данных Турвизора, не меняются. Изменения реквизитов пишутся в аудит.

Повторная сверка прежде копировала заказчика, связанного с другими договорами, оставляя прежний уникальный exchange_id. Это вызывало IntegrityError, ошибочно показанный как повторное создание договора. Теперь подтверждённое обновление выполняется в общей карточке с сохранением PK/UUID и связей, без дублей. Сообщение об иных конфликтах целостности больше не утверждает причину без доказательств.

Диалог заказчика из журнала Договоров прежде строил URL из локализованного числового ID: у карточек с ID>=1000 появлялся разделитель тысяч. В URL добавлен unlocalize. Регрессионный тест проверяет корректный путь, ответ200, SAMEORIGIN и15строк примечания.

Проверки: прямое/веб/групповое ограничение старых ID без записи, граничный допустимый ID, обновление общей карточки с сохранением UUID/связей/локальных данных, необязательное обновление при первом импорте и сравнение выбранной карточки без записи. Изменений схемы базы нет.
