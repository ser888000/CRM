# Согласование после тренировочного переноса

## Изменение 1 — единый справочник способов оплаты

Статус: **реализовано в корректирующем пакете повторного переноса**. Изначально правило было только сохранено; включено в новый перенос после следующих уточнений владельца.

В новой CRM один справочник «Способы оплаты» используется в Договорах и Финансах. В старой CRM это два разных источника:

- Финансы: исходный код способа оплаты/счёта → новое значение по таблице ниже.
- Документы: поле «Статус документа» → значение того же нового справочника по последней колонке таблицы. Это правило заполнения способа оплаты договора, не новый независимый статус договора.

Исходные коды финансов и коды статусов документов — разные пространства идентификаторов. Не сопоставлять их численно. Для документов проверить справочник статусов и поле связи (по изученной схеме LIST_DOCUMENTS.ID_PRIZNZK_DOC / PRIZNAK_DOCUMENTS) перед реализацией. Пустая ячейка статуса в таблице не задаёт правила для документов: не угадывать соответствие и не переносить туда способ оплаты из платежа автоматически.

Для данного правила меняются только справочные привязки. Суммы, даты, договоры, плательщиков и исходный архив не изменять. Применяется при повторном переносе новым пакетом, с согласованной очисткой тренировочных данных.

## Корректирующий пакет повторного переноса

- Числа в таблицах выровнены вправо.
- Город вылета ← «Начало путешествия», регион ← «Пункты пребывания», ночи ← первые 1–2 цифры в начале «Продолжительность» перед пробелом (или концом значения).
- «Тайланд» → «Таиланд»; «Кемерово/Новосибирск» → «Кемерово».
- Ненулевая суммарная оплата ТО создаётся одной финансовой операцией со способом «Тинькофф р/с» и датой оплаты ТО. Без даты полного расчёта используется дата договора; дата полной оплаты в договоре остаётся пустой. Накопленный начальный остаток обнуляется, чтобы исключить двойную себестоимость. Отрицательная сумма сохраняется как возврат ТО.
- Туристы пополняют справочник и связываются со строками. Строгое совпадение нормализованных ФИО, даты рождения и паспорта позволяет повторно использовать карточку; исторический снимок строки остаётся отдельным. Это новое указание владельца, заменяющее прежнее «только строки, без справочника».
- Невыполненные задачи связываются с внутренним ID последнего договора заказчика (дата/время источника, затем исходный ID при равенстве). Выполненные остаются без договора. Если договора у заказчика нет, задача остаётся общей. В карточке также показаны общие задачи этого заказчика; их редактирование не создаёт связь с договором автоматически.
- Перед новым переносом разрешено очистить Договоры, Задачи, Финансы и справочники. Сохранять Библиотеку, Шаблоны задач, Операции, Валюты, Города вылета, Страны и учётные записи пользователей. Типы, необходимые сохранённым шаблонам задач, восстанавливаются со связями. Очистка и импорт — одна транзакция после резервной копии.
- При заполненных верхних поисковых полях Договоров/Задач/Финансов период не ограничивает поиск, но сохраняется. При сбросе условий или применении пустых полей снова действует сохранённый период. Сброс везде ссылкой, в Задачах отделён от блока дат; кнопки статусов сохранены.
- Заказчики: большие варианты фильтров загружаются по поиску, без тысяч элементов в HTML. Турист в строке выбирается через поиск, весь справочник не повторяется в каждой форме. Админка Договоров: суммы рассчитаны SQL-подзапросами и общей агрегацией вместо запросов для каждого документа.
