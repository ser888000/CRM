# Согласование после тренировочного переноса

## Изменение 1 — единый справочник способов оплаты

Статус: **только сохранить, пока не реализовывать**. Правило передано владельцем после успешной загрузки тренировочной истории.

В новой CRM один справочник «Способы оплаты» используется в Договорах и Финансах. В старой CRM это два разных источника:

- Финансы: исходный код способа оплаты/счёта → новое значение по таблице ниже.
- Документы: поле «Статус документа» → значение того же нового справочника по последней колонке таблицы. Это правило заполнения способа оплаты договора, не новый независимый статус договора.

Исходные коды финансов и коды статусов документов — разные пространства идентификаторов. Не сопоставлять их численно. Для документов проверить справочник статусов и поле связи (по изученной схеме LIST_DOCUMENTS.ID_PRIZNZK_DOC / PRIZNAK_DOCUMENTS) перед реализацией. Пустая ячейка статуса в таблице не задаёт правила для документов: не угадывать соответствие и не переносить туда способ оплаты из платежа автоматически.

Несколько старых кодов объединяются в одно новое значение «Другое». Дополнительные значения «Счет», «Терминал», «Кредит», «МИР» нужны для сопоставления статусов документов даже без указанного кода финансов. Названия сохранить в написании владельца.

При последующей реализации менять только справочные привязки. Суммы, даты, договоры, плательщиков и исходный архив не изменять. Пока приложение, правила импорта и загруженные данные не меняются.
