# Согласованный состав импорта Tourvisor

Основание: пользовательские пометки от 22.10.2026, сохранены в examples/tourvisor-user-field-notes.md. Это спецификация следующего этапа, не реализация импорта.

## Идентификация и даты

- В процессе агентства `id` онлайн-заявки используется как номер договора клиента. Сохранять также отдельным неизменяемым идентификатором связи с Tourvisor, с указанием типа «онлайн-заявка»; по нему исключать дубли и запрашивать обновления.
- `date` используется как дата договора; сохранять исходные `date` и `time` Tourvisor. Эти полученные из Tourvisor реквизиты не редактируются пользователем.
- Ручные договоры по-прежнему создаются с текущей датой и внутренним автоматическим ID; идентификатор Tourvisor не выдумывать.

## Заказчик

Импортировать ФИО, адрес, основной телефон/email, дату рождения и отдельные реквизиты паспорта РФ (номер, дата выдачи, орган выдачи, код подразделения).

Добавить отдельные текстовые поля «Дополнительные телефоны» и «Дополнительные email». Эти локальные данные сохранять при повторном импорте; не заменять их одним основным контактом из API.

## Тур и справочники

Импортировать комментарий, ТО, город вылета, страну, дату вылета, ночи, название тура, общую стоимость, валюту, ссылку ТО, количество взрослых/детей/младенцев.

ТО, города вылета, страны — справочники с кодами Tourvisor, если доступен соответствующий источник кодов. Фактический ответ ordersonline.php содержит для этих полей названия, а не коды. Не выдумывать коды и не считать кодами наши внутренние ID. До реализации проверить доступность справочников и однозначное сопоставление названий. Не обещать, что имеющийся ключ экспорта открывает поисковый API.

Валюта — справочник. Текущие финансовые расчёты агентства остаются рублёвыми; валюту исходного предложения не принимать за рубли без явного согласованного преобразования.

`manual` пока сохранять как технический признак исходных данных, без влияния на бизнес-правила; назначение уточнить.

## Туристы

Нужны все перечисленные поля туриста: серия/номер/тип паспорта, выдача/срок действия/орган выдачи, раздельные фамилия и имя, пол, дата и страна рождения, гражданство, isclient. Учитывать фактическое имя `isclient` в ответе API. Связь с заказчиком проверять; не объединять людей только по транслитерации.

## Проживание

Импортировать весь массив hotel: название, страна, регион, дата заселения, ночи, номер, питание, размещение. Страну связывать со справочником при подтверждённом сопоставлении. Не ограничивать структуру одним отелем.

## Перелёты

Импортировать весь массив transport, без ограничения двумя рейсами: направление, номер, даты/время, авиакомпания, самолёт, аэропорты и их коды.

Ниже структурированного списка предоставить отдельное многострочное текстовое поле для вставки перелётов из документов ТО при ручном вводе. Оно не требует заполнения отдельных полей рейсов и не затирается повторным импортом. Сформировать читаемое представление импортированных рейсов для задачи проверки вылета; сохранять также локальные текстовые дополнения.

## Услуги

Импортировать названия всех услуг. service[].startdate не переносить в рабочие поля и не показывать в карточке.

## Обновления и сбои

Перед применением обновлений показывать различия; сохранять местные платежи, себестоимость, задачи, брони и дополнительные текстовые поля. Возможность получения актуального состояния по ID ещё проверить экспериментально.

При ошибке/тайм-ауте/неожиданном ответе показывать понятное сообщение, не создавать частичный договор и не изменять существующий. Ключи и персональные данные не выводить в ошибки и журналы. Остальные отложенные изменения сохранены в PLAN.md.
