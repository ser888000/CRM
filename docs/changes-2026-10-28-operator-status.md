# Полный расчёт с ТО и общий срок броней

Дата полной оплаты ТО заменена boolean operator_paid_in_full. Миграция0038 сначала добавляет статус, отмечает все записи с непустой operator_paid, затем удаляет старое поле. Финансы не пересоздаются/не изменяются. Обратная миграция не восстанавливает утраченные даты; для них нужна резервная копия до обновления.

Статус доступен в журнале Договоров и во вкладке Финансы договора: зелёное Оплачено, нейтральное Не оплачено, переключение без перехода со страницы. POST+CSRF, view/change_contract, блокировка строки и версия updated_at защищают сохранение. Меняется только статус, дата изменения и аудит, финансовые записи не создаются. При конфликте/сбое показывается ошибка и предлагается обновить страницу. Успешное изменение обновляет версии собственных форм карточки; основной ModelForm исключает статус и срок, чтобы обычное сохранение не сбрасывало их.

Срок оплатыТО остаётся общим Contract.operator_due и вынесен одним полем в начало вкладки БрониТО. Одна дата используется для всех броней, журнал отображает тот же срок. Отдельное сохранение имеет проверку версии и аудит. Основной способ оплаты расположен после ТО в блоке Основное; Примечание занимает всю строку. Блок старых платёжных полей убран, Метрика остаётся в Дополнительно.

Копирование договора сбрасывает отметку полного расчёта. При новом импорте старой CRM статус определяется наличием исходной даты; сама дата используется для перенесённого платежаТО, затем в договоре не хранится.

Проверки:249 тестов, проверка модели/миграций и JavaScript. Дополнительная миграция копии истории подтвердила5487 отметок по старым датам и побайтовое равенство12856 финансовых строк до/после. Реальная рабочая база обновляется штатным веб-обновлением с резервной копией.
